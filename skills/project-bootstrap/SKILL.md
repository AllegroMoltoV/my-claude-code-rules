# プロジェクト初期セットアップ

新しいプロジェクトを開始可能な状態まで持っていく。機械的な作業はスクリプトに任せ、判断が必要な部分だけを自分で行う。

## 手順

### 1. セットアップスクリプトの実行

カレントディレクトリを対象に実行する。何度実行しても結果が変わらないため、既にセットアップ済みかどうかを事前に確認する必要はない。

```bash
bash "${MY_CLAUDE_RULES}/scripts/bootstrap.sh"
```

`MY_CLAUDE_RULES` は、このルール集のリポジトリを clone した位置を指す環境変数である。未設定であれば利用者に位置を尋ね、推測でパスを組み立てない。

このスクリプトが行うのは次の内容である。リポジトリへは一切書き込まない。

- `~/.claude/rules/` へのルール配置と、本 skill の symlink 登録
- git リポジトリの初期化 (ブランチは main)
- `.git/info/exclude` への除外設定の追記
- `.appendix`、`.tmp`、`.logs`、`.prompts/PLANS`、`.prompts/DISCUSSIONS`、`docs/reports`、`docs/logs` の作成
- `.prompts/INIT.md` の配置
- `docs/INDEX.md` の雛形作成
- Beads の初期化 (`bd init --stealth --skip-agents --non-interactive --init-if-missing`)

出力の `[warn]` は必ず利用者に伝える。`[info]` は伝えなくてよい。

Beads を使わないプロジェクトでは、先に `touch .beads-optout` を実行してからスクリプトを走らせる。

### 2. 要件の記入

利用者から要件を聞いている場合は、`.prompts/INIT.md` の要件セクションに転記する。まだ聞いていない場合は、この時点で確認する。

要件が曖昧なまま調査に進んではいけない。何を作るのかが決まっていないと、調査の範囲が定まらない。

### 3. 現状の調査

要件に関連する情報を、非破壊的な操作で可能な限り収集する。

- ファイルの読み取り、ディレクトリ構造の確認、`git log` の参照
- 利用可能な MCP サーバーがあれば参照系の操作で外部情報も収集する
- 公式ドキュメント、既存の設定ファイル、依存関係の確認

大量のファイル読み込みや丁寧な分析が必要な場合はサブエージェントに委譲する。独立した調査は並列に走らせる。

調査結果は `docs/reports/` に保存し、`docs/INDEX.md` に 1 行追記する。

推測と、コマンドやドキュメントで確認した事実を混ぜてはいけない。確認した内容には確認方法を添える。

### 4. 長期タスクの登録

調査の結果、複数セッションにまたがる作業になると判断した場合は Beads に登録する。

```bash
bd create --title="..." --description="..." --type=epic --priority=1
bd create --title="..." --description="..." --type=task --priority=1 --parent=<epic-id>
bd dep add <後続タスク> <先行タスク>
```

数分から数十分で終わる単発作業は登録しない。迷ったときは登録する。

### 5. 不明点の洗い出し

調査を踏まえてもなお不足している情報や曖昧な点を洗い出す。調査で判明した事項は質問に含めない。

質問は「聞いて利用者の判断や自分の作業が変わるか」を基準に絞る。変わらない質問は削除する。細目を並べず、本質的な問い 1 つに集約し、残りは推奨案を添えた提案型で確認する。

洗い出した内容は `.prompts/QUESTIONS.md` に保存する。

保存後、利用者に回答を促し、回答を待ってから次の作業に進む。

## 完了時の報告

次の内容を簡潔に伝える。

- セットアップで作成したもの、および `[warn]` として出た事項
- 調査で確定した事実と、まだ確認できていないこと
- Beads に登録したタスクと依存関係
- 利用者が今この時点で判断すべきこと。無ければ判断事項なしと明記する
